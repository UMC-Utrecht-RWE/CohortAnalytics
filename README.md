### Parameters in practice (refactoring priorities)

- `compute_rates_cohort`: always passed constant — `type="incidence"`, `CImethod="wilson"`, `CumulativeInc=FALSE`, `comparison_measures=TRUE`, `end_risk=NULL`, `output_format="data.frame"`, `minimum_count_for_comparative=3`. Candidates for defaults or removal.
- `compute_rates_cohort`: genuinely varied — `aesifup_input, fupCol, pyrCol, pyr_offset, eventCol, iptw, target_aesi, scale_IR, risk_type, model_based_control, weighted_IR`.
- `compute_rates_cohort`: newer, project-specific — `idCol, timeVar, incidence_model` (case-study-08, time-varying), `unique_person_cols, model_library, chunksize` (case-study-01, IPCW/bigglm).
- `risk_type` is only passed as `"incidence"` (or a variable in case-study-07); the log-binomial branch has been removed in the current source.
- `est_inc_prev`: `n_pat, n_out, py, type, scale_IR` are used everywhere; `CImethod` only in the RSV projects.
- Internal functions (`fitmod_gee`, `extract_ests_gee`) are called via `:::` in the RSV projects, so changing their signatures breaks those projects.
- Projects pinned to old branches/SHAs will not pick up refactors until upgraded; unpinned ones (case-study-10, paxlovid-*) will.

### Where `compute_rates_cohort()` parameters go (internal flow)

Traced from the current [R/compute_rates_cohort.R](R/compute_rates_cohort.R). Parameters marked "not in current source" were passed by projects on other branches but are not arguments of this file's `compute_rates_cohort()`; they must be re-added or the calls updated when refactoring.

| Parameter                                                | Varied / project-specific                               | Fed to                                                                                                                              |
| -------------------------------------------------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `aesifup_input`                                        | varied                                                  | all steps; `fitmod_gee`, `est_inc_prev`, `create_risk_table`, `estimate_HR`                                                 |
| `eventCol`                                             | varied                                                  | event counts; model formula (`event ~ group + offset(...)`) in `fitmod_gee`; `create_risk_table`; `estimate_HR`             |
| `pyrCol`                                               | varied                                                  | person-year sums per group, which feed `est_inc_prev` (analytic IR)                                                               |
| `pyr_offset`                                           | varied                                                  | `offset()` term in the formula passed to `fitmod_gee` (then `extract_ests_gee`, `est_inc_prev_model`)                       |
| `fupCol`                                               | varied                                                  | `create_risk_table`, `estimate_HR`; max follow-up when `comparison_measures`                                                  |
| `iptw`                                                 | varied                                                  | adjusted `fitmod_gee` (weights), `create_risk_table`, `estimate_HR` (`model_type="adj"`)                                    |
| `target_aesi`                                          | varied                                                  | label in output; `aesi_name` in `fitmod_gee`, `create_risk_table`, `estimate_HR` (logging)                                  |
| `scale_IR`                                             | varied                                                  | `est_inc_prev`, `est_inc_prev_model`, `extract_ests_gee`, `create_risk_table`                                               |
| `model_based_control`                                  | varied                                                  | switches control-group IR between `fitmod_gee` + `est_inc_prev_model` (TRUE) and `est_inc_prev` (FALSE)                       |
| `weighted_IR`                                          | varied                                                  | if TRUE, exposed (and control if model-based) IR uses weighted `fitmod_gee` + `est_inc_prev_model`; else `est_inc_prev`       |
| `risk_type`                                            | varied (case-study-07)                                  | `"survival"`: `create_risk_table` (KM) and `estimate_HR`; otherwise `extract_ests_gee` (IRR/IRD)                            |
| `idCol`, `timeVar`, `incidence_model`              | project-specific (case-study-08, not in current source) | no consumer in this file; GEE clustering currently comes from `person_id_num` inside `fitmod_gee` (via `process_cohort_data`) |
| `unique_person_cols`, `model_library`, `chunksize` | project-specific (case-study-01, not in current source) | no consumer in this file; presumably the `geeM`/`bigglm` fitting path in `fitmod_gee` on that branch                          |

Constant arguments: `type` and `CImethod` go to `est_inc_prev`; `type` also labels `rr_type`/`rd_type`; `CumulativeInc`, `comparison_measures` and `end_risk` control the `create_risk_table` branch; `minimum_count_for_comparative` masks RR/RD with -77; `output_format` only sets the return class.

Note: with `risk_type="incidence"` (as every project uses), `create_risk_table` and `estimate_HR` are never reached, so `fupCol`, `CumulativeInc`, `end_risk` and `comparison_measures` have no effect on the estimates in the incidence-only path (only `comparison_measures=TRUE` gates the RR/RD block).
